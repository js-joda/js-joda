HowTo update tzdb data
======================

The tzdb data of `@js-joda/timezone` is generated by the private package
[`@js-joda/tzdb-builder`](../tzdb-builder) directly from the official
[IANA releases](https://www.iana.org/time-zones). The generated files in `data/` are committed,
CI does not generate them.

# Prerequisites

Node >= 20, `make`, a C compiler (`cc`), `tar` and network access to `data.iana.org`.
The builder compiles `zic` from the IANA tzcode of the same release, a `zic`/`zdump` installed
on the machine is never used.

# Steps

1. Find the release to use, the latest one is listed at <https://data.iana.org/time-zones/tzdb/version>
   (see its `NEWS` for the changes).

2. Generate the data:

   ```bash
   cd packages/tzdb-builder
   npm install
   npm run generate -- latest          # or an explicit version, e.g. 2026e
   ```

   This writes into `packages/timezone/data/`:
   - `unpacked/latest.json` and `unpacked/<version>.json`
   - `packed/latest.json`, `packed/<version>.json` and the reduced range files `packed/latest-*.json`

   Single steps can be repeated with `--step <name>` or `--from <name>`
   (`fetch → compile → collect → write-unpacked → pack`), `--force` downloads the release again.

3. Optional: compare the result with moment-timezone data of the same release, if available:

   ```bash
   npm run parity -- <moment-timezone>/data/unpacked/<version>.json .cache/<version>/unpacked.json --until 2499
   ```

   It must report `Unexpected differences: 0`.

4. Build and test the timezone package:

   ```bash
   cd ../timezone
   npm run test-ci
   ```

5. Commit the changed files below `packages/timezone/data/` and add a CHANGELOG entry.

Note that the relative range files (`-4-year-range`, `-10-year-range`, `-60-year-range`,
`-300-year-range`, `-lifetime-range`) depend on
the year of generation, so regenerate the data at least once a year.
