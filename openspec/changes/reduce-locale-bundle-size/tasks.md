# Tasks

Decisions (see `design.md`): shipped in the same major as `explicit-plugin-data-registration` (Q7,
2026-11-01: no second stage, no separate minor); no `/slim` or `/slim-no-zone-names` entries; the root
of `@js-joda/locale` bundles only `weekData`; the prebuilt `localeData` includes the `likelySubtags`
subset of its languages; `zoneNames` and `metaZones` are separate values to register;
`@js-joda/locale/likely-subtags` exports the full file; `registerLocaleData` merges `likelySubtags`
parts until the full file is registered and clears cached `Cldr` instances; the cldrjs bundle queue
is guarded so a thrown error never poisons later lookups (design decision 3); the clear errors are
`DateTimeException`s, always on and rest on registered data; the zone-ID parse cache is invalidated
on registration. All paths below are relative to `packages/locale` unless noted.

## 3. Registering data in CldrCache

- [ ] 3.1 In `src/format/cldr/CldrCache.js`, track whether the full `likelySubtags` is registered (the tagged `{ full: true, path, data }` value of `/likely-subtags`, recognised by `registerLocaleData`, and the file loaded from the `cldr-data` source), merge parts of `supplemental/likelySubtags.json` until the full file is registered and ignore them afterwards, keep first-wins for every other path, and clear the cached `Cldr` instances on every `Cldr.load` (design decisions 3). Also add the cldrjs bundle-queue guard: before creating a `Cldr` instance, re-feed the registered `main/*` bundles whose language has a `likelySubtags` entry into the cldrjs available-bundle queue (or reset the queue and reload), because cldrjs drops a queued bundle when a lookup throws and first-wins-by-path would then skip the `Cldr.load` that would restore it. Keep bundles whose language has no entry out of the queue until it is registered, because cldrjs drains the whole queue on any `new Cldr`. Verify with tests in `test/format/cldr/CldrCacheTest.js`: two parts are both resolvable, the same object twice has no effect, a part after the full file changes no value, a second `metaZones` or `main/*` registration is skipped, data registered after `WeekFields.ofLocale(new Locale('ko', 'KR'))` is used for `Locale.KOREAN`, and the recovery scenario: register `main/th` without `likelySubtags`, let a format throw, then register the full `likelySubtags` — formatting with `new Locale('th', 'TH', 'th')` and another registered locale both work afterwards. Use `main/th` test data from `cldr-data`; add no new `Locale` constants. Also test that while `th` has no entry, other locales and `WeekFields` keep working
